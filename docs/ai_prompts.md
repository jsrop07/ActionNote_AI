# AI 활용 기록

## 사용한 AI 도구

* **Figma AI**: React 기반 한 페이지 UI 초안 설계
* **Gemini CLI**: 기존 React UI를 유지한 상태에서 FastAPI 백엔드와 연결하기 위한 프로젝트 구조 분석 및 연결 틀 생성
* **ChatGPT**: 기능 범위 정리, 백엔드 구현 순서 설계, 오류 원인 분석, 테스트 케이스 작성 및 결과 검증

이번 과제에서는 AI에게 전체 결과물을 한 번에 맡기기보다, 역할을 나누어 활용했습니다.
Figma AI는 화면 구조를 잡는 데 사용했고, Gemini CLI는 프론트와 백엔드 연결을 위한 기본 틀을 만드는 데 사용했습니다. 이후 실제 백엔드 로직 구현, 오류 수정, 테스트 케이스 설계는 ChatGPT와 대화하면서 단계별로 확인하며 진행했습니다.

## 1. Figma AI — React UI 초안 설계

### 사용 목적

처음부터 코드를 작성하기 전에, 이 도구가 사용자에게 어떤 흐름으로 보여야 하는지 먼저 정리하고 싶었습니다.
단순히 입력창과 결과 표만 있는 화면이 아니라, “입력 → AI 분석 → 검증 → 문서 저장” 흐름이 한 페이지에서 보이도록 UI 구조를 잡기 위해 Figma AI를 사용했습니다.

### 입력한 프롬프트

ActionNote AI라는 업무 자동화 웹앱의 한 페이지 UI를 디자인해줘.

이 서비스는 자유 형식 회의록, 업무 메모, 문서 파일을 입력하면 AI가 내용을 분석해서 요약, 결정사항, 실행 항목, 담당자, 마감일, 리스크, 누락 정보를 자동 정리해주는 도구야.

전체 분위기는 개발회사 내부에서 실제로 사용할 수 있는 깔끔한 업무용 SaaS 느낌이면 좋겠어. 너무 화려하거나 장난스러운 느낌보다, 신뢰감 있고 정돈된 생산성 도구처럼 보여야 해.

화면은 데스크톱 기준 1440px 너비의 한 페이지 대시보드 형태로 구성해줘.

상단 Hero 영역:

* 서비스명: ActionNote AI
* 짧은 설명: 자유 형식 회의록과 문서 파일을 AI로 분석해 업무 후속 조치를 자동 정리합니다.
* 보조 설명: 요약, 결정사항, 실행 항목, 리스크, 누락 정보를 구조화하고 Google Docs로 저장할 수 있습니다.
* 오른쪽에는 처리 흐름을 시각화한 작은 카드: 입력 → AI 분석 → 검증 → 문서 저장

메인 입력 영역:

* 좌측에는 입력 카드
* 탭 2개: 텍스트 입력 / 파일 업로드
* 텍스트 입력 탭에는 큰 textarea
* 파일 업로드 탭에는 PDF, DOCX, XLSX, TXT 지원 안내와 드래그 앤 드롭 업로드 박스
* 분석하기 버튼은 명확하게 보이게 배치

분석 결과 영역:

* 상단에 요약 카드
* 그 아래에 간단 대시보드 카드 4개:

  1. 실행 항목 수
  2. 담당자 미정
  3. 마감일 미정
  4. 리스크 수
* 각 카드는 숫자가 크게 보이고, 작은 설명 텍스트가 있으면 좋겠어.

결과 상세 영역:

* 탭 또는 섹션으로 구성

  1. 결정사항
  2. 실행 항목
  3. 리스크
  4. 누락 정보
* 실행 항목 테이블 컬럼:
  할 일 / 담당자 / 마감일 / 우선순위 / 원문 근거
* 원문 근거는 evidence_text라는 개념으로, AI 결과를 사용자가 검증할 수 있게 보여주는 용도야.

저장 영역:

* Google Docs 문서 이름 입력창
* 이름을 비워두면 “YYYY-MM-DD_회의록”, “YYYY-MM-DD_회의록_1” 형식으로 자동 저장된다는 안내 문구
* Google Docs로 저장 버튼
* Markdown 다운로드 버튼은 보조 버튼으로 배치

하단 검증 포인트 영역:

* AI가 원문에 없는 담당자나 마감일을 추측하지 않도록 미정 처리
* 각 결과에 원문 근거 evidence_text 표시
* 파일 입력은 텍스트로 추출한 뒤 동일한 분석 흐름으로 처리
* PDF 표 추출은 일부 순서가 섞일 수 있어 사용자가 검토하도록 안내

디자인 스타일:

* 배경은 아주 연한 회색 또는 흰색
* 카드 기반 레이아웃
* 둥근 모서리
* 적당한 그림자
* 포인트 컬러는 블루 또는 인디고 계열
* 업무용 B2B SaaS 느낌
* 폰트는 깔끔한 sans-serif
* 너무 많은 색을 쓰지 말고, 중요 정보만 강조

최종 결과는 개발자가 React + TailwindCSS로 구현하기 쉽게 컴포넌트 단위가 분명한 레이아웃으로 만들어줘.

### 반영한 내용

Figma AI가 만든 한 페이지 UI를 기반으로 React 화면을 구성했습니다.
분석 전에는 안내 카드만 보이도록 하고, 분석 후에 요약 카드, 대시보드, 상세 결과, Google Docs 저장 영역이 나타나도록 수정했습니다.
또한 화면 하단에 검증 포인트를 배치해, 이 도구가 단순 요약기가 아니라 AI 결과를 원문 근거와 함께 검토하는 구조라는 점이 보이도록 했습니다.

## 2. Gemini CLI — 프론트와 백엔드 연결 틀 생성 전 구조 분석

### 사용 목적

Figma AI로 만든 React UI는 있었지만, 바로 백엔드 코드를 붙이면 기존 UI 구조가 깨질 수 있다고 판단했습니다.
그래서 Gemini CLI에게 전체 구현을 맡기지 않고, 먼저 프로젝트 구조와 mock data 위치, API 연결이 필요한 부분만 분석하게 했습니다.

### 입력한 프롬프트

먼저 현재 프로젝트 구조를 분석해줘.

목표는 Figma AI로 만든 React UI와 FastAPI 백엔드를 연결하는 거야
아직 코드는 수정하지 말고, 아래 내용만 정리해줘

1. 현재 frontend 폴더 구조
2. 현재 backend 폴더 구조
3. React UI에서 mock data를 쓰는 위치
4. API 연결이 필요한 컴포넌트
5. 백엔드에 필요한 API 목록
6. 수정해야 할 파일 목록
7. 새로 만들어야 할 파일 목록
8. 구현 순서

중요:
아직 파일을 수정하지 말고
먼저 분석 결과와 작업 계획만 알려줘

### 반영한 내용

Gemini CLI가 React UI 내부의 mock data 위치와 API 연결이 필요한 영역을 정리해 주었고, 이를 바탕으로 FastAPI 백엔드 구조를 만들었습니다.
이후 실제 OpenAI 호출, 파일 파싱, Google Docs 저장 로직은 자동 생성에 맡기지 않고 직접 코드를 확인하면서 단계별로 구현했습니다.

## 3. ChatGPT — 백엔드 구현 순서 설계

### 사용 목적

Gemini CLI로 기본 틀을 만든 뒤, 어떤 순서로 실제 동작하는 백엔드를 채워야 할지 정리하기 위해 사용했습니다.
한 번에 파일 업로드와 Google Docs 저장까지 모두 붙이면 오류 원인을 찾기 어려울 것 같아서, 텍스트 분석 API부터 단계적으로 구현하기로 했습니다.

### 입력한 프롬프트

Gemini CLI로 React UI와 FastAPI 백엔드를 연결하기 위한 기본 폴더와 파일 틀을 만들었어

현재 목표는 전체 기능을 한 번에 완성하는 것이 아니라, 내가 코드를 하나씩 확인하면서 실제로 동작하게 만드는 것이고
우선순위는

1. FastAPI 서버 실행 확인
2. /api/analyze-text 텍스트 분석 API 먼저 구현
3. OpenAI API 호출 결과를 summary, decisions, action_items, risks, missing_info 구조로 반환
4. 담당자, 마감일, 우선순위가 명확하지 않으면 “미정” 처리
5. 각 항목에는 evidence_text를 포함해 원문 근거를 확인할 수 있게 하기
6. 그 다음 TXT, DOCX, PDF, XLSX 파일 업로드 분석을 순서대로 붙이기
7. 마지막으로 Google Docs 저장 기능을 붙이기

이 순서가 맞는지 확인해 주고, 먼저 backend/services/ai_service.py와 schemas/analysis.py를 어떤 구조로 작성하면 좋을지 알려줘
단, 코드에는 파일 역할과 함수 역할을 주석으로 남겨서 나중에 수정할 때 어느 부분을 고쳐야 하는지 알 수 있게 해줘

### 반영한 내용

텍스트 분석 API를 먼저 완성한 뒤, Swagger에서 `/api/analyze-text`를 테스트했습니다.
OpenAI 응답을 JSON으로 파싱하고, 프론트에서 사용하기 쉬운 `AnalysisResult` 구조로 반환하도록 만들었습니다.
이후 파일 입력도 결국 텍스트로 정규화한 뒤 동일한 `analyze_text()` 흐름을 재사용하도록 설계했습니다.

## 4. ChatGPT — 오류 원인 분석 및 검증

### 사용 목적

구현 중 API가 정상적으로 호출되지 않는 문제가 발생했습니다.
처음에는 파일 파서 문제라고 생각했지만, 실제로는 프론트와 백엔드의 API 경로가 맞지 않는 문제일 수 있다고 판단해 원인 분석을 요청했습니다.

### 입력한 프롬프트

파일 업로드 기능을 테스트하는데, TXT나 DOCX 어떤 파일을 올려도 Not Found가 발생하고있어
현재 FastAPI는 backend/main.py에서 router를 등록하고 있고, routers/analyze.py에도 APIRouter가 있어
프론트에서는 analysisApi.ts에서 analyzeFile 함수를 통해 파일을 업로드하고있는데

이 상황에서 어느 파일들을 먼저 확인해야 하는지 알려줘
특히 Swagger에 실제 등록된 경로와 프론트에서 호출하는 경로가 다를 가능성이 있는지 확인하고싶고
파일 파서 자체의 문제가 아니라 API 경로, router prefix, FormData field name, Vite proxy 중 어디가 문제인지 순서대로 확인할 수 있게 알려줘

### 반영한 내용

확인 결과 `main.py`와 `routers/analyze.py` 양쪽에서 `/api` prefix를 붙이고 있어 실제 경로가 `/api/api/analyze-file`로 등록되는 문제가 있었습니다.
Swagger에서 실제 등록된 API 경로를 확인한 뒤, router 내부의 중복 prefix를 제거해 `/api/analyze-file`로 맞췄습니다.
이 과정을 통해 AI가 제안한 구조를 그대로 믿기보다, 실제 실행 결과와 API 문서를 비교하며 수정하는 방식으로 진행했습니다.

## 5. ChatGPT — 비정형 메모 테스트와 결과 점검

### 사용 목적

정형 회의록뿐 아니라, 실제 업무 중에 아무렇게나 적은 메모에서도 결정사항, 할 일, 리스크, 누락 정보를 잘 구분하는지 확인하고 싶었습니다.
이를 위해 일부러 담당자/마감일이 명확한 항목과 애매한 항목, 보류한 기능, 리스크, 결정사항이 섞인 긴 테스트 텍스트를 작성해 달라고 요청했습니다.

### 입력한 프롬프트

제출 전 마지막으로 테스트하려고하는데

회의 내용을 정리한 것이긴 하지만, 정식 회의록이 아니라 작업하면서 아무렇게나 적은 메모에서도 제대로 분석되는지 확인하고 싶다.
아래 조건을 포함한 긴 테스트 텍스트를 작성해줘.

1. 확정된 결정사항이 있어야 함
2. 담당자와 마감일이 명확한 할 일이 있어야 함
3. 담당자 또는 마감일이 애매한 할 일도 있어야 함
4. 보류하거나 제외하기로 한 기능이 섞여 있어야 함
5. OAuth 인증, PDF 추출, 보안 파일, 제출 시간 부족 같은 리스크가 있어야 함
6. 실제 회의록처럼 깔끔하게 정리된 문서가 아니라, 사람이 작업하면서 적은 비정형 메모처럼 작성해줘
7. 이 텍스트를 분석했을 때 decisions, action_items, risks, missing_info가 제대로 분리되는지 확인할 수 있게 만들어줘

### 반영한 내용

비정형 메모를 입력해 분석했고, 결과가 결정사항, 실행 항목, 리스크, 누락 정보로 분리되는지 확인했습니다.
특히 Google OAuth 인증 문제, PDF 표 추출 한계, OpenAI JSON 응답 실패 가능성, 보안 파일 노출 위험이 리스크로 분리되는 것을 확인했습니다.
또한 담당자나 마감일이 명확하지 않은 항목은 “미정”으로 처리되도록 후처리와 프롬프트를 점검했습니다.
